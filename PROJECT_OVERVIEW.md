# Project Overview: Goalytics

## Summary

Goalytics analyzes football match video and presents live tactical metrics in a browser dashboard. The system is organized as a three-part pipeline:

1. A Python computer vision agent processes video frames.
2. A FastAPI backend exposes the agent's generated files as API endpoints.
3. A React frontend visualizes live stats, video streams, heatmaps, and processed footage.

The current implementation is designed for local development and demo workflows, where the detector, backend, and frontend run as separate processes on the same machine.

## Core Workflow

```text
Input video
   |
   v
agent/agent.py
   |
   v
YOLOv8 detection + tracking + team/referee/ball logic
   |
   v
data/live_stats.json + data/live_frame.jpg + processed video + heatmaps
   |
   v
backend/server.py
   |
   v
React frontend dashboard
```

## Main Components

### 1. Computer Vision Agent

Location: `agent/agent.py`

The agent is the analytics engine. It reads a match video, runs YOLO detections, tracks objects, annotates frames, and writes live outputs for the backend.

Key responsibilities:

- Detect people and sports balls using YOLOv8 COCO classes.
- Track detections with Ultralytics tracking, using ByteTrack by default.
- Classify non-referee players into two teams using jersey color clustering.
- Detect likely referees with jersey color heuristics.
- Filter detections by pitch polygon and grass-foot checks when configured.
- Smooth and recover ball location with a Kalman filter.
- Estimate ball possession by nearest player-to-ball distance.
- Count team touches, player touches, passes, and possession percentages.
- Generate radar points when homography is configured.
- Estimate shots, shots on target, and goals from ball movement in pitch coordinates.
- Write live frame and stats files for the dashboard.
- Generate team heatmaps after processing completes.

Important outputs:

- `data/live_stats.json`
- `data/live_frame.jpg`
- `agent/output_detection.mp4`
- `agent/team1_pitch.png`
- `agent/team2_pitch.png`

### 2. Backend API

Location: `backend/server.py`

The backend is a lightweight FastAPI app that serves files generated by the agent. It does not perform detection itself.

Main routes:

- `/stats`: returns `data/live_stats.json`.
- `/analysis-frame`: returns the latest annotated frame.
- `/analysis-stream`: streams frames as MJPEG.
- `/heatmaps`: lists generated heatmaps.
- `/heatmaps/team1` and `/heatmaps/team2`: serve team heatmap images.
- `/videos`: lists playable video files in `agent/`.
- `/videos/{video_name}`: serves a selected processed video.

The backend enables CORS for the Vite development frontend at `localhost:5173` and `127.0.0.1:5173`.

### 3. Frontend Dashboard

Location: `frontend/`

The frontend is a React + Vite app. It polls the backend for stats, displays live analysis, and provides pages for match-level and team-level views.

Main routes:

- `/dashboard`: live dashboard with teams, possession, scoreboard, tracking metrics, heatmaps, and stream preview.
- `/insights`: team-specific analytics and heatmap view.
- `/analysis-stream`: large live annotated stream.
- `/videos`: processed video selector and player.

The API base URL is resolved in `frontend/src/api.js`. During Vite development on port `5173`, it defaults to `http://127.0.0.1:8765`.

## Data Contract

The frontend expects `/stats` to return fields such as:

- `timestamp`
- `frame`
- `fps`
- `players_detected`
- `team1_players`
- `team2_players`
- `referees_detected`
- `ball_detected`
- `ball_available`
- `ball_source`
- `possession_team`
- `ball_owner_track_id`
- `team1_possession_pct`
- `team2_possession_pct`
- `team1_touches`
- `team2_touches`
- `player_touch_counts`
- `radar_points`
- `player_distance`
- `team1_goals`
- `team2_goals`
- `team1_shots`
- `team2_shots`
- `team1_shots_on_target`
- `team2_shots_on_target`

Some fields depend on configuration. For example, shot and goal fields are available when homography is configured; otherwise `shot_detection_available` is set to `false`.

## Technology Stack

### Python

- FastAPI for the backend API.
- OpenCV for video I/O, frame annotation, image processing, and Kalman filtering.
- NumPy for numeric operations.
- PyTorch and Ultralytics YOLO for detection and tracking.
- EasyOCR optionally for jersey number recognition.

### Frontend

- React.
- Vite.
- React Router.
- Lucide React icons.
- Recharts.

## Typical Local Run Order

1. Start the backend:

```bash
uvicorn backend.server:app --reload --port 8765
```

2. Start the frontend:

```bash
cd frontend
npm run dev
```

3. Start the detector:

```bash
python agent/agent.py --video agent/RMvsLVP2.mp4 --model yolov8m.pt --no-show
```

Once the detector starts writing `data/live_stats.json` and `data/live_frame.jpg`, the dashboard should update automatically.

## Current Assumptions

- The project is primarily local-first.
- Video files are expected in `agent/` for the `/videos` page.
- Generated heatmaps are expected in `agent/`.
- Live stats and live frame files are expected in `data/`.
- Team names and colors in the frontend are currently initialized as Liverpool and Real Madrid defaults.
- The agent defaults to `agent/RMvsLVP2.mp4`, so users should pass `--video` if using a different file.

## Suggested Next Improvements

- Add a root `requirements.txt` or `pyproject.toml` for reproducible Python setup.
- Move team names, colors, and match metadata into a shared config file.
- Add sample `.env` files for frontend and backend ports.
- Add automated tests for API routes and frontend data formatting helpers.
- Store completed match runs in separate folders instead of overwriting live output files.
